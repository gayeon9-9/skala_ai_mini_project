# 4단계 — FAQ·Runbook 의미 검색과 출처 제공

시작 커밋: `9f9df9b`. 선택한 시스템을 MCP로 점검한 뒤 실제 임베딩으로 문서를 검색하고
검색 본문을 답변 생성 문맥에 전달한다. 선택 없이 호출하는 기존 실습 API는 비교용으로 유지한다.

| 기존 문제 | 개선 | 효과 |
|---|---|---|
| 모니터링 알림 키워드로 Runbook 하나를 선택 | 자연어 증상으로 사용자 FAQ, 증상·관측 알림으로 운영자 Runbook 검색 | 서로 다른 표현의 문의에서도 관련 안내를 찾을 기반 확보 |
| 사용자 안내와 운영자 절차의 구분 없음 | 용도·대상 시스템으로 문서 범위 제한 | 사용자에게 운영자용 내부 조치 문맥이 섞이는 문제 방지 |
| 근거 문서와 답변의 연결이 불명확 | 문서 ID 인용, 제목·ID 출처 카드, 결과 저장 | 어떤 문서를 참고했는지 다시 확인 |
| 관련 문서가 없을 때 기본 유형 사용 가능 | `no_match`와 검색 실패 `error`를 구분, 임의 기본 문서 없음 | 근거 부족을 사용자와 관리자에게 명확히 전달 |
| 미검증 초안 전송·최대 시도 강제 합격 | 토큰 초안 전송/표시 제거, 검증 실패 시 제한된 관측 안내 | 확인되지 않은 초안이 최종 조언처럼 보이지 않음 |

## 파일별 역할

- `agent/retrieval.py`: Ollama 임베딩, 캐시 색인, 용도·대상 필터, 문서별 검색 결과.
- `data/knowledge_catalog.json`, `data/faq/`: 사용자 FAQ와 기존 운영 Runbook의 문서 메타데이터.
- `tools/build_rag_index.py`: 별도 색인 준비. 서버는 동일 검색기를 의존성 주입한다.
- `agent/graph.py`: MCP 점검 → 사용자/운영자 검색 → 답변 생성 → 검증 연결.
- `agent/answer_generation.py`, LLM 어댑터: 공통 근거·인용 프롬프트, fake 시연 답변, 제한된 실패 안내.
- `agent/chat_service.py`, `inquiry_store.py`, `server.py`: 검색·검증 결과 응답과 저장.
- `web_chat.html`: 검증 전 초안 제거, 검색 상태·출처·검증 실패 표시 및 복원.
- `tests/test_retrieval.py`, `test_rag_flow.py`, `test_answer_generation.py`: 검색 규칙과 생성 문맥·실패 종료 검사.

## 실제 검색과 시연 생성의 구분

임베딩 모델은 `qwen3-embedding:0.6b`이고, 현재 머신에 모델을 추가 설치했다.
기존 생성 모델은 삭제하지 않았다. 모델 API의 배치 임베딩을 사용하며 색인은 `.rag_cache/`
아래에 저장하고 Git에서 제외한다. 모델·문서가 바뀌면 캐시를 다시 만든다.

`LLM_BACKEND=fake`여도 실행 서버의 RAG는 실제 임베딩 검색이다. 다만 최종 문장 생성은
고정 시연 코드다. 자동 테스트의 가짜 검색기는 별도이며 실제 검색 정확도를 뜻하지 않는다.
임베딩 모델이 없거나 Ollama 연결이 실패하면 검색 실패를 표시하고 원인·조치를 추측하지 않는다.

사용자 FAQ 본문은 생성 문맥에 들어간다. 운영자 Runbook은 별도 검색 결과로 저장하며,
사용자 응답에는 넘기지 않는다. 문서의 유사도는 장애 발생 확률이나 원인 확정 점수가 아니다.

## 최소 검증과 다음 단계

`.venv/bin/python -m pytest -q` — 87개 및 45 subtests 통과. 검색 필터·캐시 무효화·
손상 벡터·검색 실패·출처 전달·운영자 자료 분리·최대 실패 종료·초안 비노출을 검사했다.

이번에는 기존 형식 검증 실패가 3회 누적되면 `fallback`으로 종료한다. 검증에 합격했다고
바꾸지 않는다. 대체 안내는 코드가 샘플 관측값·관련 문서 제목·추가 확인 사항만 구성한다.
5단계에서 출처 ID·선택 대상·관측 수치 및 근거 부족 표현을 추가 검사한다.

Ollama의 구조화 JSON 호출은 생각 출력 없이 최대 생성 길이를 제한하도록 조정했다.
일반 답변과 정보 추출의 품질이 향상됐다는 주장은 별도 평가 결과가 필요하다.
API 옵션 근거: [Ollama 공식 Chat API](https://docs.ollama.com/api/chat).

실제 의미 검색 평가 결과와 최종 비교 화면은 6단계 통합 기록에 모은다.
