# 3단계 — 자연어 문의 정보 추출과 후속 질문

시작 커밋: `2dc8559`. 사용자가 정해진 양식을 입력할 필요 없이 자연어를 계속 입력한다.

| 기존 | 개선 | 효과 |
|---|---|---|
| 메시지 원문만 저장 | 증상·발생 시각·오류 메시지·사용 환경을 구조화 | 관리자 확인에 필요한 항목을 일정한 형태로 준비 |
| 후속 문장이 짧으면 최초 증상 문맥을 잃기 쉬움 | 이전 접수 필드와 현재 발화를 병합 | “오전 9시요”라고 답해도 로그인 증상 유지 |
| 없음·모름·누락을 구분하지 않음 | 네 가지 상태를 명시적으로 저장 | “오류 메시지가 없어요”라고 답했는데 다시 묻는 문제 방지 |
| 모델 추출 결과의 원문 근거가 불명확 | 스키마·원문 발췌·없음/모름 표현을 검사 | 임의 날짜·환경을 접수 사실로 저장하는 일부 오류 차단 |

## 파일과 흐름

- `agent/intake.py`: 필드 스키마, 근거 검사, 병합, 질문 선택, 명시적 규칙 대체 경로.
- `agent/intake_llm.py`: 기존 LLM 어댑터들이 공유하는 JSON 추출 지시와 스키마.
- `agent/fake_llm.py`, `ollama_llm.py`, `openai_llm.py`: 같은 `extract_intake` 인터페이스.
- `agent/graph.py`: `route → intake → plan` 연결, 누적 접수 문맥 전달, 추가 질문 부착.
- `agent/chat_service.py`, `inquiry_store.py`, `server.py`: POST/SSE에서 동일한 접수 결과 저장·응답.
- `web_chat.html`: 네 필드 카드, 이전 저장 정보 표시, 새 문의 초기화, 새로고침 복원.
- `tests/test_intake.py`, `test_chat_persistence.py`, `test_web_proxy.py`: 추출·병합·저장·화면 상태 검사.

`자연어 → LLM 추출(fake는 규칙) → 원문 근거 검사 → 기존 필드와 병합 → 미확인 항목 한 가지 질문`.
선택 시스템은 추출 항목에 포함하지 않아 AI가 대상을 바꾸지 못한다. 제공된 값은 원문의
연속 부분 문자열이어야 하며 발생 시각에 임의 날짜를 붙이지 않는다. `unmentioned`는
기존 값을 지우지 않는다. 한 번 질문했는데 답하지 않은 항목은 계속 재질문하지 않고
미확인 상태로 남겨 관리자가 확인할 수 있게 한다.

접수 정보와 질문 상태는 최종 답변 저장 시 함께 확정한다. 답변 생성 실패로 질문이
전달되지 않았는데 “이미 물어봄” 상태만 남는 것을 막는다. 기본 점검은 미확인 항목이
있어도 진행한다. 장애 원인 확정이나 운영 조치는 아직 수행하지 않는다.

## 검증과 한계

`.venv/bin/python -m pytest -q` — 61개 및 38 subtests 통과.

단위 테스트에는 모델 환각 발췌 제거, 없음/모름, 시간 원문 보존, 후속 발화 병합,
중복 질문 방지, 비정상 JSON·모델 오류, 비동기 어댑터가 포함된다. API 테스트는 POST
접수 후 SSE 후속 답변을 보내고 서버 복원 결과가 일치하는지 확인한다.

실제 `qwen3:0.6b`에 합성 문의 한 건을 입력한 결과, 모델 출력이 스키마/원문 근거 검사를
통과하지 못해 `rules_fallback`으로 전환되었다. 명시된 네 필드는 규칙으로 추출했지만,
이를 소형 모델의 추출 정확도 향상으로 설명하지 않는다. 범용 한국어 이해에는 더 큰 모델,
추가 평가와 오류 분석이 필요하다. `source`와 `warnings`에 대체 처리 여부를 기록한다.

원문 포함 검사는 의미 판단 전체를 증명하지 않는다. 상태·필드 귀속의 의미 오류는 남을 수
있으므로 관리자 화면에서 원문과 대조할 수 있도록 보존한다. OpenAI 실 API 호출은 이번
검증에서 실행하지 않았다. 본 기능의 자동 테스트는 외부 서비스 없이 반복 가능하다.
