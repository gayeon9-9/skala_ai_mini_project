# 5단계 — 근거와 답변 일치 검사

시작 커밋: `f47d979`. 4단계에서 초안 비노출과 실패 종료를 고쳤고, 이번에는 합격 기준을 강화한다.

| 기존 | 개선 | 사용자·관리자 효과 |
|---|---|---|
| 길이·번호만 맞으면 합격 | 선택 대상, 인용 문서 ID, 관측 수치의 일치 검사 | 그럴듯한 형식의 잘못된 답변 일부 차단 |
| 반려 이유가 짧은 답변이라는 문구로 고정 | 실제 실패 항목을 재작성 피드백으로 전달 | 모델이 어떤 부분을 고쳐야 하는지 명확히 제시 |
| 최종 답변만 보면 검증 결과 불명확 | 상태·반려 이유·인용 ID 저장 | 관리자가 검증 실패 및 제한된 안내 여부를 확인 |

## 파일과 처리

- `agent/answer_validation.py`: 문자열 형식, 대상·출처·관측값·검색 상태·단정 표현 규칙 검사.
- `agent/graph.py`: 검사 결과에 따라 제한된 재작성 후 합격 또는 `fallback` 종료.
- `tests/test_answer_validation.py`, `test_rag_flow.py`: 잘못된 수치·문서·대상 차단, 정상 답변
  및 실패 종료를 확인한다. 모델 호출 없이 검증기 자체를 반복 검사한다.

`초안 → 근거 일치 검사 → 실패 항목 전달 → 최대 3회 작성 → 확인된 정보로 제한한 안내`.
재시도 한도에 도달해도 합격으로 바꾸지 않는다. 모델이 만든 잘못된 마지막 초안은 화면에
표시하거나 최종 답변으로 저장하지 않는다. 내부 실행 기록에는 검증 이유를 남긴다.

검증 전 토큰은 4단계부터 비공개다. 합격/대체 안내는 접수 저장 트랜잭션 이후 사용자에게
보낸다. 관리자 기능은 같은 저장된 결과를 읽으므로 별도의 추측 요약을 만들지 않는다.

## 검증

5단계까지 전체 **107개 테스트·63개 하위 사례 통과**. 정상 근거 답변,
수치·출처·대상 오류, Markdown 수치 강조, 원인 불확실성 표현과 3회 실패 후 종료를 확인했다.
개발 중인 6단계 평가 도구 테스트는 이 수치에서 제외했다.

## 한계

이 검증기는 명시적 규칙으로 찾을 수 있는 오류를 차단한다. 문서 ID가 맞더라도 문장 의미가
문서와 일치하는지까지 완전하게 증명하지는 못한다. 새 표현이나 복잡한 수치 서술은 누락될 수
있으며, 반대로 정상 문장의 오차단도 확인해야 한다. 정답을 알고 있는 잘못된 답변 사례와
정상 답변 사례를 함께 측정하고, 결과를 전체 환각 탐지 정확도라고 부르지 않는다.

RAG 검색 점수 역시 실제 장애 원인의 확률이 아니다. 현재 지표는 샘플이므로 실제 오류 로그와
사용 환경 확인이 필요하다는 안내를 유지한다. 추가 운영 조치를 자동 실행하지 않는다.
