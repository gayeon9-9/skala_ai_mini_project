## 촬영 도구 실패도 보존

첫 문의는 앱에서 54.262초에 정상 완료했으나, 촬영 스크립트가 빈 입력창의 비활성 전송 버튼을 잘못 완료 조건으로 사용해 240초 후 시간 초과했다. 앱 오류가 아닌 촬영 자동화 오류다. `automation_attempt_1/`에 실패 화면·검증 원문·API·trace를 보존했다. 조건을 고친 후 **동일 합성 질문을 새 문의로 한 번 더 전송**해 최종 캡처를 만들었다. 따라서 임시 관리자 목록에는 동일 질문 접수 2건이 보인다. 두 실행 모두 LangSmith readback을 확인했으며 실패한 모델 응답을 선별 제거한 것이 아니다.

## 남은 한계와 해석 주의

- 검색 결과에는 `faq:connectivity`(504 문서)가 계속 보존되어 UI/관리자에 표시된다. 이번 보완은 검색 결과 삭제가 아니라 **미확인 오류 코드가 든 문서를 답변 생성 근거에서 제외**하는 방식이다.
- 답변에 ‘고부하’, ‘원인일 수 있음’ 등의 해석과 브라우저 문서의 관련성을 부정하는 문장이 남았다. 규칙 통과가 모든 문장의 의미적 타당성/장애 원인 정확성을 보장하지 않는다. 이 한계를 원문과 화면에서 숨기지 않았다.
- 실제 로그·운영 지표·복구 실행·관리자 인증을 검증한 자료가 아니다.
- 입력이 네 필드를 모두 포함하므로 이번 실측은 추가 질문 경로를 검증하지 않는다. 해당 흐름은 별도 회귀 검사/이전 단계 근거를 사용한다.
- 로컬 Qwen의 `usage.usd` 표시는 가상 단가 계산으로 실제 청구액이 아니다. 이번 시연에서 실제 비용 비교를 주장하지 않는다.
